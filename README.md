# ARS Coursework: Offline-to-Online RL on CartPole and Acrobot

One DQN agent (`rl/`) is used in three configurations on CartPole-v1 and Acrobot-v1:
**1. pure online**, **2. pure offline (CQL)**, **3. offline-to-online (O2O)**.
Task 3 adds uncertainty-guided online data collection (ActiveRL-style).

**To see everything, open `results/RESULTS.md`** (tables, figures, settings). Regenerate it with
`python summarise.py` after any new run. Project notes and decisions are in `CLAUDE.md`.

## Setup

```bash
python -m venv .venv
# Windows: .venv\Scripts\activate      Mac/Linux: source .venv/bin/activate
pip install -r requirements.txt
```

In VS Code pick the `.venv` interpreter (Ctrl+Shift+P, "Python: Select Interpreter").

## How to run (all scripts take `--env CartPole-v1|Acrobot-v1` and `--seed N`)

```bash
# 0. Offline datasets (random and medium), written to data/
python make_dataset.py --env CartPole-v1 --policy both

# 1. Pure online DQN
python train_online.py --env CartPole-v1 --seed 0

# 2. Pure offline: CQL on a dataset (--policy random|medium), no game steps while learning
python train_offline.py --env CartPole-v1 --policy medium --seed 0

# 3. Offline-to-online: starts from the SAME seed's offline model, so run step 2 first
python train_o2o.py --env CartPole-v1 --policy medium --seed 0

# Summary of everything: tables, figures, results/RESULTS.md
python summarise.py
```

Extras: `plot.py` (quick curves for one env), `summarise_offline.py` (offline table and curves),
`watch_online.py` (live pygame view of CartPole training; writes no files).

## Layout

```
rl/            shared code: config, network, replay buffer, DQN agent, evaluation, paths, utils
data/          offline datasets (.npz) and their average returns (.json)
results/
  online/<env>/s<seed>/              eval.csv, episodes.csv, summary.json, model.pt
  offline/<env>/<dataset>/s<seed>/   eval.csv, summary.json, model.pt
  o2o/<env>/<dataset>/s<seed>/       eval.csv, episodes.csv, summary.json, model.pt
  figures/                           all plots
  archive/                           old or superseded runs (not used in tables)
  RESULTS.md                         generated by summarise.py
logs/          console output of batch runs
tools/         one-off helpers (migrate_results.py)
```

Folder paths are defined in one place, `rl/paths.py`.

## How one online training step works (`train_online.py`)

1. **Act:** pick an action epsilon-greedily and step the environment.
2. **Store:** add (s, a, r, s', terminated) to the replay buffer.
3. **Learn:** every `train_freq` steps run `gradient_steps` updates, each on a random minibatch.
4. **Sync:** every `target_update` steps copy the online network into the target network.
5. **Evaluate:** every `eval_every` steps run the greedy policy for 10 episodes and log the mean.

CQL (offline) adds a penalty to the loss that pushes down scores of actions the dataset never shows.
O2O loads the offline weights, keeps the dataset in the replay buffer next to new online data, and plays.
